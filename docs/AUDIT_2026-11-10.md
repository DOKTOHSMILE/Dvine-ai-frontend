# Codebase audit — 2026-11-10 (0.99.41)

Scope: the Android app (`app/`): 398 Java files and 80,800 lines of main code, plus 161 test files and 16,000 lines of tests. The audit covered:
- the manifest and permissions;
- secrets and key storage;
- network security, TLS and downloads;
- shell execution and approvals;
- shared state and threads;
- unused code;
- Android lint (`lintDebug`);
- test coverage by package;
- the bugs reported from the device on 2026-11-10.

## Fixed in 0.99.41

## Checked and sound

- **No secrets in the code or resources.** API keys and the device secret are encrypted with AES-GCM keys held in the Android Keystore (`ProviderStore`, `DeviceVault`).
- **The custom trust manager is safe** (`ProviderStore.sockets`). It still checks the full certificate chain against the phone's authorities, then against a CA the user pasted. Hostname verification is not replaced.
- **Cleartext traffic is off** except `localhost` and the emulator host. `allowBackup` is false. Every component except the launcher is `exported="false"`.
- **WebViews:** JavaScript is on where sign-in needs it (social login, Google), and file access is off in all four.
- **Shell commands from Ibiko go through `allowRun`.** The user approves each one unless they chose Auto. Commits, pushes and pull requests are asked separately.

## Open: recommended next work, in order

1. **Only one job runs at a time across all chats.** While Ibiko codes in one conversation, a message in another waits; since 0.99.41 it says so and is sent afterwards. Running pages truly in parallel needs the reply state (`generating`, `streamOpen`, the live steps) to be per page. Today it lives once, in `MainActivity`.
2. **`MainActivity` is 6,000 lines** and holds every page's state. This is the root of the leak class fixed above. Continue the split (task #73): a per-page `Job` object owning its id, page, steps, live text and stop.
3. **The Termux path is still live** (`ops/termux/*`, `ops/TermuxAndroid`, the `RUN_COMMAND` permission and the `com.termux` package query in the manifest), although the shell no longer uses Termux. Remove it, or route it to `LinuxHub`, and drop the permission.
4. **18 classes nothing in the app uses** (about 1,600 lines; most are referenced only by their own tests): `render/forms/Sculpt`, `agent/TermuxRunner`, `create/ObjImporter`, `ops/pipe/SemanticGraph`, `agent/Debate`, `ops/recon/ReconstructionJob`, `ops/pipe/CreationRouter`, `llm/SpeechChunker`, `llm/ToolHow`, `agent/ViewIntent`, `ops/pipe/MachinePlan`, `turn/Followup`, `ops/task/VoiceInterruptionManager`, `ops/mind/ResponseStreamingManager`, `ops/recon/ReconstructionQualityChecker`, `render/field/PhotoFrame`, `llm/AnswerGate`, `llm/WorldLookup`. Delete them, or wire them if they are planned.
5. **Thin tests in `ops/`** (87 files, 6 test files) and `main/` (12 files, 2 test files). This is where task routing and page switching live.
6. **36 raw `new Thread(`, and 14 `catch (Throwable`** that hide failures. Move them to a few named executors, and log what is caught.
7. **Lint, minor:** 108 hard-coded strings (`SetTextI18n`, `HardcodedText`), so no translation is possible. 8 touch handlers without `performClick` (accessibility). 21 unused resources.
8. **Two replies to one message** in the gpt-5 screenshot ("Good morning…" then "I hear you clearly…"). Not reproduced here. It looks like the "Still working" follow-up answering as well as the first call. Needs a device log.
